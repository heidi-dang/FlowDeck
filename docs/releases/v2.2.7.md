# FlowDeck v2.2.7

FlowDeck v2.2.7 introduces a major **OpenCode-native simplification refactor**, aligning Heidi's architecture strictly with the official OpenCode runtime capabilities (v1.18.18).

## Overview & Background

FlowDeck's core architectural invariant is that **FlowDeck owns Heidi-specific intelligence, while OpenCode owns the execution lifecycle and authoritative state.** Prior to v2.2.7, FlowDeck maintained several redundant systems (shadow lifecycles, loop guards, approval states, custom generic output context limits, and custom shell execution lifecycles) which competed with OpenCode's native capabilities.

This release strips out duplicate runtime machinery, ensuring that FlowDeck acts purely as an intelligence and orchestration layer relying on the OpenCode host for execution, file access, and process isolation.

## Key Architecture & Features in v2.2.7

### 1. Complete Delegation to OpenCode Native Tools
- **Removed Duplicate Machinery**: Deleted custom shadow lifecycles, `approval-service.ts`, `loop-detector.ts`, `shell-executor.ts`, `shell-command-classifier.ts`, `recovery-coordinator.ts`, `task-phase-manager.ts`, and custom context generic handlers.
- **Native Tool Integration**: FlowDeck no longer overrides native tools (`shell`, `bash`, `read_file`, `write_file`). A missing FDX binary degrades cleanly to OpenCode native tools instead of maintaining parallel TypeScript implementations.

### 2. Upgraded OpenCode Targeting
- FlowDeck is now strictly targeted at the **OpenCode v1.18.18 plugin architecture and runtime**. Compatibility declarations in `package.json` and TypeScript interfaces have been updated to reflect this required baseline.

### 3. FDX Caching Simplification
- Cross-platform FDX caching is now clean without duplicate machinery.
- The repository relies entirely on the host environment to manage execution contexts, reducing FlowDeck's footprint and resolving previous CI blockers.

## Verification & Production Gates
