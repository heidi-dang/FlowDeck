# FlowDeck v1.0.3 — Release Integrity Repair

Repairs the release pipeline blocker that prevented v1.0.2 from publishing.

## What's Fixed

### npm registry availability check under `bash -e`

The v1.0.2 tag-triggered publish workflow (run 30671638543) failed at the `Check Registry Availability` step before npm publish was attempted.

GitHub Actions runs shell steps with `bash -e` (errexit). The step executed:

```bash
LOOKUP_OUTPUT="$(npm view "@heidi-dang/flowdeck@${PKG_VERSION}" version 2>&1)"
LOOKUP_EXIT=$?
```

When npm returns E404 for an unpublished version — the **expected** state for a first publish — the command substitution exits non-zero and `bash -e` terminates the step immediately, before `LOOKUP_EXIT=$?` can be captured. The healthy "not yet published" state therefore incorrectly failed the workflow.

The step now:

1. Reads the version from `package.json`.
2. Temporarily disables errexit **only** around the `npm view` assignment and exit-code capture (`set +e` ... `set -e`, smallest possible scope).
3. Classifies outcomes explicitly:
   - exit 0 → version already published → **FAIL** (duplicate publish blocked)
   - exit != 0 with npm E404 "No match found for version" → not published → **continue to npm publish**
   - anything else (E401 authentication, ENETUNREACH/registry-unavailable, ENOTFOUND/DNS, ETIMEDOUT/timeout, SSL failures, malformed responses, unexpected npm errors) → **FAIL**

No `|| true`, no ignored exit codes, no globally-disabled errexit, no masking of npm failures.

## Release-workflow regression coverage

- `tests/release-registry-check.test.ts` (9 tests): executes the **exact extracted step body** from `publish.yml` under `bash -e` with a mocked `npm` binary, covering unpublished E404 (continues), published version (blocks), authentication, network, DNS, timeout, unexpected npm errors, the errexit regression, and command-substitution capture. **0 pass / 9 fail against the v1.0.2 workflow; 9 pass / 0 fail against v1.0.3.**
- `tests/publish-workflow-order.test.ts`: invariant 8 strengthened to require `set +e`/`set -e` scoping, `LOOKUP_EXIT` capture, and the E404 "No match found for version" classification.

All other release hardening remains intact: Bun pinned to 1.3.14, tag/version alignment, build-before-test ordering, `npm pack --dry-run --json` content validation, `npm publish --provenance --access public`, and least-privilege permissions (`contents: read`, `id-token: write`).

## Compatibility

**No runtime configuration migration is required.** No user-facing runtime changes are included in this release; it is a release-pipeline integrity release.
