# FlowDeck v2.2.6

FlowDeck v2.2.6 is a production hotfix release resolving the Heidi orchestrator-guard false-positive loop, pending-tool state leaks, and UI event flooding observed in v2.2.5.

## Overview & Symptoms Resolved

In v2.2.5, Heidi sessions executing repository discovery workflows could become blocked at `0/N todos completed` when legitimate developer inspection commands (such as `node -p 'require("./package.json").version'`, `bun test`, and `cargo test`) were categorized as unknown or mutating shell commands. Blocked commands could retry in an unbounded loop, and pending-tool tracking slots were not released at the guard boundary.

FlowDeck v2.2.6 delivers precision classification, bounded circuit invalidation, leak-free lifecycle state management, and clear replanning guidance.

## Key Changes in v2.2.6

1. **Inspection & Test Command Classification**:
   - Pure read-only inspection rules added in `shell-command-classifier.ts` for `node -p` / `node --print` / `node -c`, `bun test` / `bun -p` / `bun run test|typecheck|lint|check|verify`, `cargo test|check|clippy|fmt --check`, and `npm|pnpm|yarn|deno test`.
   - Security invariants preserved: genuine mutating commands (`rm`, `git commit/push`, `npm install`, `cargo publish/build`) and sensitive path reads (`.env`, `~/.ssh`, `*.pem`, `*.key`) remain strictly guarded.

2. **Bounded Retry Strategy & Circuit Invalidation**:
   - Guard fingerprints now incorporate working directory (`cwd`) to guarantee distinct operation identity across project subdirectories.
   - Repeated unchanged attempts on a blocked operation are marked with `ORCHESTRATOR_GUARD_STRATEGY_INVALIDATED` (`terminal: true`, `recoverable: false`), terminating retry loops after attempt 1.

3. **Lifecycle & Watchdog State Cleanup**:
   - Guard rejections properly release call timers, decrement `sessionActiveTools`, and clear `watchdogState.isPendingTool`.
   - Guard circuit breaker history is cleared upon session cleanup and task phase transitions.

4. **Structured Heidi Replanning Guidance**:
   - Machine-readable structured error feedback instructs Heidi that identical commands cannot be retried unchanged, presenting actionable alternatives (FDX tools: `fdx-read`, `fdx-search`, `fdx-ls`, and specialist routing: `@coder`, `@tester`, `@debug-specialist`).

5. **Cross-Platform Compatibility**:
   - Supported Windows path separators in fast-lane token parsers and hardened test lifecycle teardown against Windows `EBUSY` locks.
