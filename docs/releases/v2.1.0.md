## Heidi Fast Harness v1

FlowDeck v2.1.0 introduces **Heidi Fast Harness v1**, a major architectural upgrade that transforms Heidi from a monolithic direct executor into a high-throughput, route-first coordinator with lean live context and hot-path performance optimizations:

- **Route-First Task Execution**: Deterministic per-user-task classification (`HeidiFastRouter`) classifies intent on Turn 1 before running expensive repository discovery or heavyweight planning. Manual user turns are classified immediately, while internal recovery prompts preserve active route state without reclassification.
- **FAST_DIRECT Path**: Trivial local tasks (single-file bug fixes, minor config edits, typos, small refactors, focused documentation updates) execute immediately across a streamlined lifecycle: classify → inspect → edit → focused verify → done, eliminating planning and coordinator overhead.
- **Immediate Specialist Delegation**: Dedicated domain tasks delegate directly to specialists on Turn 1 (`@debug-specialist` for failing test triage and root causes, `@security-auditor` for security audits, `@frontend-coder` for UI components) without intermediate exploration turns.
- **Frontend / Backend Parallel Specialist Routing**: Multi-domain tasks with disjoint file ownership route concurrently to `frontend-coder` and `backend-coder` specialists, backed by the newly added `BACKEND` domain.
- **82.3% FAST_DIRECT Prompt Reduction**: The always-on permanent coordinator prompt is decoupled from dynamic catalogs, reducing the prompt from 2,933 tokens down to 518 tokens (82.3% measured reduction).
- **Live Per-Turn Lazy Context**: The permanent core prompt remains static and lightweight (<900 tokens), while specialist directories, workflow stage rules, domain catalogs, and execution constraints are injected lazily per turn based on the active execution class.
- **3.82× Measured Read-Batching Speedup**: The `ReadBatchService` parallelizes independent safe repository reads (`fdx-read`, `fdx-grep`, `fdx-search`, `fdx-outline`) concurrently, while maintaining strict serialization for all mutating operations.
- **Compact External Task State**: Semantic task state (`HeidiTaskState`) is tracked outside conversation history and injected as a compact, structured context packet (<200 tokens, ~100 tokens / 401 characters after 100 accumulated facts) rather than requiring the model to reconstruct context from long turn histories.
- **Repository Hot-Context Cache**: In-memory cache (`RepositoryHotContext`) retains project root, Git HEAD SHA, active branch, language detection, package manager, build/test commands, layout summary, and FDX status, with deterministic invalidation upon Git HEAD changes, configuration modifications, or manifest updates.
- **Config Cache**: High-speed cached configuration resolution (`ConfigCache`) eliminates repeated synchronous disk reads and JSON/JSONC parsing for FlowDeck configuration, supervisor settings, agent model mappings, and governance mode.
- **Governance Read Fast Path**: Accelerated authorization (`GovernanceFastPath`) provides near-zero overhead (<2 ms p50 target; measured ~0.0001 ms) for verified read-only inspection tools on clean paths, while routing all file writes, deletions, and shell executions through the full strict governance engine.
- **In-Memory Token-Accounting Hot Index**: In-memory index on `FileTokenUsageStore` serves hot usage and budget queries in O(1) without requiring full JSONL log rereads on active turns.
- **Buffered Non-Critical Audit Persistence**: Informational audit events are buffered in memory and flushed periodically or at batch thresholds, while critical governance events (policy blocks, destructive operation denials, recovery exhaustion, security mismatches, delegation events) continue to flush synchronously.
- **Deterministic Tool-Call Repair**: Rule-based repair mechanically normalizes common schema variants, parameter aliases (e.g., `path` vs `file_path`, `cmd` vs `command`), path separators, and scalar/array shapes before triggering additional model inference turns.

## Reliability

FlowDeck v2.1.0 maintains strict runtime reliability and preserves all v2.0.9+ safety invariants:

- **Session Log Writable Fallback**: Retains the resilient session log fallback to ensure diagnostic continuity even in non-standard file permission environments.
- **Root `/.opencode` EACCES Fix**: Retained permission safety and fallback paths when encountering root directory EACCES errors.
- **Hardened Recovery Pipeline**: Retains all v2.0.9 recovery protections, including reasoning-only completion recovery, provider replay sanitization, manual user message supersede handling, and leak-free cancellation timer cleanup.
- **Zero Spurious Continues**: Healthy workload auto-Continue count remains strictly 0, preventing accidental prompt injection or runaway continuation loops.

## Performance (measured, this release)

The following real measurements were benchmarked in this release:

- **FAST_DIRECT Prompt**: 518 tokens vs 2,933 baseline = 82.3% reduction
- **Read-Heavy Operations (4 independent reads)**: 164.0 ms sequential → 42.9 ms parallel = 3.82× speedup
- **Read-Only Governance Fast Path p50**: 0.00008 ms (p95: 0.00024 ms)
- **Performance Tracing p50**: 0.00025 ms (p95: 0.00141 ms)
- **Routing Latency p50 (user → route)**: ~0.001 ms
- **Task-State Packet**: ~401 chars (~100 tokens) after 100 accumulated facts
