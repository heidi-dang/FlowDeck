# FlowDeck v2.0.0-alpha.4

Date: 2026-08-11

Status: **PRERELEASE**. This is an `alpha` development release. It is NOT "stable" and NOT promoted to `latest` on the npm registry.

## Publication status

- v2.0.0-alpha.4 **supersedes the failed/unpublished v2.0.0-alpha.3 publication attempt**.
- The `v2.0.0-alpha.3` tag remains an **immutable historical release record** (tag object `51d5eb30…`, peeled commit `1a2e695`). It was **not** successfully published to npm; it is **not** moved, deleted, retagged, or republished.
- alpha.4 is the first published candidate of the post-M9 v2 line on the `alpha` npm dist-tag.

## Highlights

- M1-M9 V2 autonomous execution: 9/9 milestones CLOSED, Master Plan 100%.
- Canonical executable commands (task/start, plan, execute, verify, complete, review/audit, resume/recover, status) with durable idempotency (20-way).
- Scheduler/workstream/Assignment dispatch with durable assignment binding.
- Canonical token governance, worktree isolation, ownership controls.
- Canonical verification, evidence, and six-gate Completion Engine.
- Fresh-runtime recovery R1-R15: nonterminal resume after process restart, terminal projection with zero rerun, concurrent-recovery single-flight, historical command-version preservation.

## Fixes in this release

- **Schema fail-closed release-runner fix**: `scripts/check-schema-generated.mjs` now honours the *detected* `sqlite3` CLI path (`findSqlite3Cli()` result) through the validation boundary instead of invoking a literal `sqlite3` from PATH. A detected-but-broken or replaced SQLite executable fails closed (non-zero exit) and can no longer be silently bypassed by a real `sqlite3` on PATH. This is the exact regression that failed the alpha.3 tag-triggered publish run (`31480180293`, `tests/check-schema-fallback.test.ts`) before npm publication.
- Completion regression: real VerificationResult/Evidence reach the Completion Engine on the required-verification path (current-SHA gate no longer starved).
- Worktree integration gate no longer bypassed (agent verificationPassed is authoritative).
- Cancellation cascades to logical Assignments (no zombie assignments).
- Recovery claim acquisition serialized (BEGIN IMMEDIATE); SHA-scoped recovery fast-path.

## Known limitations (alpha)

- Semver prerelease: 2.0.0-alpha.4 does not imply stable-channel guarantees.
- Verification-reuse fast-path still re-verifies on recovery (outcome-correct, decision deduped) — see milestone evidence.

## Upgrade and migration notes

- Migration v7 (assignment binding) is additive and idempotent; prior V2 alpha databases migrate forward cleanly.
- No configuration migration is required for v1 users staying on `latest`.

  `npx @heidi-dang/flowdeck@alpha install`
