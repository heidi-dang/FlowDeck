# FlowDeck v2.0.0-rc.1

Date: 2026-08-13

Status: **RELEASE CANDIDATE (RC.1)**, published under `next` npm dist-tag.

## Overview

FlowDeck v2.0.0-rc.1 introduces productionized runtime identity verification, installer reliability enhancements, and strict state machine lifecycle enforcement for OpenCode plugin loading.

## Runtime Identity Verification & Installer Reliability

- **Doctor packaging path resolution fix**: Productionized `resolveDoctorEngineUrl` helper handling both source (`src/`) and compiled (`dist/`) execution contexts, URL decoding, paths with spaces/Unicode, and missing asset diagnostics.
- **FlowDeck Runtime Identity**: Created canonical `FlowDeckRuntimeIdentity` structure capturing executing package version, module URL, package root, source classification (`file`, `npm-cache`, `package`, `unknown`), process PID, and startup timestamp.
- **Actual OpenCode-loaded plugin self-reporting**: Plugin runtime automatically records its active identity to `.flowdeck/runtime-self-report.json` on initialization.
- **Stale OpenCode FlowDeck cache discovery & cleanup**: Installer scans all XDG/system cache paths (`XDG_CACHE_HOME`, `XDG_DATA_HOME`, `~/.cache/opencode`, `~/.local/share/opencode`) for FlowDeck-owned packages (`@heidi-dang/flowdeck@latest`, `@heidi-dang/flowdeck@alpha`, legacy `@dv.nghiem/flowdeck`, etc.) and safely cleans only FlowDeck-owned entries while preserving all unrelated OpenCode cache artifacts.
- **Doctor Config vs Loaded Runtime Mismatch Detection**: Doctor check `plugin.runtime_identity` validates that the expected plugin identity agrees with the actually executing runtime module. Returns `PASS`, `WARN_NON_BLOCKING` (for harmless unreferenced caches), or `FAIL_BLOCKING` (`FLOWDECK_RUNTIME_IDENTITY_MISMATCH`).
- **Automatic Repair & Restart-Required Semantics**: Automatic repair cleans up stale unused caches or updates config mismatch. Explicitly distinguishes `CONFIG_CHANGED` from `RUNTIME_RELOADED`, transitioning the installer to `RESTART_REQUIRED` state when OpenCode process restart is needed.
- **State Machine Pipeline**: Enforces strict transitions `DISCOVERED` -> `BACKED_UP` -> `CLEANED` -> `CLEAN_VERIFIED` -> `INSTALLED` -> `CONFIGURED` -> `RESTART_REQUIRED` -> `RUNTIME_VERIFIED` -> `DOCTOR_VERIFIED` -> `HEALTHY`.
