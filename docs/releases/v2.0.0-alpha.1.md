# FlowDeck v2.0.0-alpha.1 — v2 Integration Line

First development release of the v2 line. The `v2.0.0-alpha` branch is the next-generation integration line derived from the stable `main` lineage and contains the completed authoritative Orchestration Master Plan (Phases 0–12, **100% complete** — 12 CLOSED, 1 SUPERSEDED).

> **Pre-release.** This build publishes to the `alpha` npm channel. Stable 1.x releases remain on `latest`. No configuration migration is required from v1.x.

## What's New

### v2 integration line

The Master Plan's durable orchestration runtime is now part of the product, not an internal spec:

- **Persistence Foundation** — SQLite lifecycle, transactions, checksummed migrations, startup schema validation (`src/orchestration/persistence/`)
- **Contract System** — contract families, versions, requirements, acceptance criteria, gates (`src/orchestration/contracts/`)
- **Runtime State Model** — task runs, assignments, sessions, context items with optimistic aggregate versioning
- **Event Store** — durable events with global sequencing, correlation tracking, deterministic replay
- **Delivery Engine** — lease-based outbox worker, idempotent delivery, retry accounting, dead-letter notifications
- **Verification & Evidence** — SHA/staleness policies, rules, verification results persistence
- **Completion Engine** — atomic completion evaluation, immutable completion decisions
- **Orchestrator** — `createProductionOrchestrationRuntime` assembles the full services graph
- **Runtime Services** — machine-consumable REST API (`GET /api/v1/orchestration/...`), health checks, real metrics (JSON + Prometheus)
- **Production Hardening** — chaos, concurrency, fault-injection, negative-path, performance, compliance suites in `tests/orchestration/`

Phase 10 (UI Integration) is **SUPERSEDED** under the CLI/plugin product boundary: FlowDeck ships as an OpenCode plugin + CLI, OpenCode Core owns UI rendering, and the phase's intent is satisfied by the REST API and typed data projections.

The authoritative completion report is [`docs/master-plan/completion-matrix.md`](../master-plan/completion-matrix.md), regenerated by `npm run verify:completion-matrix`.

### Release channel derivation

- `scripts/release-channel.mjs` — single source of truth mapping `alpha.*` → `alpha`, `beta.*` → `beta`, `rc.*` → `next`, stable → `latest`, with unsupported versions rejected.
- `publish.yml` now passes `--tag "$DIST_TAG"` to `npm publish`, so `2.0.0-alpha.x` publishes under `alpha` and can never clobber `latest`.
- `scripts/release-alignment.mjs` verifies the channel mapping in the pre-push gate.
- Regression coverage: `tests/release-channel.test.ts` (3 tests) and invariant 12 in `tests/publish-workflow-order.test.ts`.

## Compatibility

**No runtime configuration migration is required.** v1.x configs, plugin registrations, and `default_agent` settings remain valid. This is a development line; the v1.0.x stable series remains supported on `latest`.

## Immutability

- All v1.0.x releases remain immutable (tags, npm packages, GitHub releases, docs).
- v2.0.0-alpha.x versions publish exclusively under the `alpha` npm dist-tag.
