# FlowDeck v2.5.0

FlowDeck v2.5.0 introduces **Repo Master**, a bounded advisory repository-intelligence capability for Heidi’s adaptive orchestration. Repo Master reuses the existing FDX workspace index and repository hot-context cache to provide compact, deterministic evidence for repository-significant work while preserving FlowDeck’s established routing, specialist-planning, execution, verification, and completion authorities.

## Key Changes

### 1. Bounded Advisory Repository Intelligence

Repo Master derives a canonical repository identity and freshness fingerprint from the resolved workspace root, Git HEAD and branch, meaningful dirty-tree state, package manifests, and FlowDeck configuration. It produces bounded scope, relevant-file, dependency, likely-test, architectural-constraint, risk, and capability evidence. It does not retain source blobs, hidden reasoning, credentials, prompts, model identifiers, native session state, verification results, or completion state.

Repo Master wraps the existing `FdxWorkspaceIndex` rather than creating a second code index. It also uses the existing repository hot-context cache for lightweight repository facts. The direct path does not consult Repo Master and does not initialize repository scans.

### 2. Authority-Preserving Heidi Integration

Heidi remains the routing and orchestration authority. The existing `SpecialistPlan` remains the sole authority for canonical target validation, specialist selection, deduplication, dependency ordering, fan-out caps, recursive-delegation denial, tool policy, and inherited model policy. Repo Master can provide bounded scope and constraints to planned specialists; it cannot introduce an agent, select a model, spawn work, schedule execution, verify a result, or complete a run.

Repo Master advice is persisted only as bounded evidence on the existing canonical routing decision for its owning run. The shared `.flowdeck/repo-master.json` state contains repository metadata only, never run-specific advice. This prevents advice from crossing runs while retaining restart-safe routing evidence in the durable orchestration store.

### 3. Freshness, Failure, and Lifecycle Safety

Advice is fresh only when it matches the current repository identity and state fingerprint. Meaningful source, HEAD, branch, manifest, configuration, and user-authored `.flowdeck` changes invalidate advice. Repo Master’s own generated metadata is the only ignored runtime state. Atomic metadata writes use unique temporary files; malformed or cross-repository metadata fails closed.

Repository-significant multi-specialist work requires advisory consultation. A required consultation failure blocks routing or dispatch explicitly rather than inventing evidence. Lifecycle dispatch revalidates required advice, and cancellation, replacement, modification, mutation observation, and restart paths cannot revive superseded advice. Existing `VerificationService` and `CompletionPolicy` remain the exclusive verification and terminal-completion authorities.

### 4. Diagnostics and Qualification

The release adds aggregate-only metrics for consultations, cache outcomes, refreshes, stale-advice observations, and latency. Snapshot diagnostics report compact advisory status, generation time, refresh time, and scope count without path, prompt, model, run, or session labels.

Qualification covers direct, single-specialist, and multi-specialist routes; cache reuse and refresh; multi-repository and run isolation; minimal and larger fixtures; malformed state; detached HEAD; package and configuration changes; user-authored `.flowdeck` changes; cancellation; replacement; restart; lifecycle dispatch boundaries; metrics cardinality; FDX parity; schema integrity; persistence; lint; build; and the normal test suite.

## Compatibility

This is a backward-compatible stable minor release. No database migration, alternate scheduler, alternate execution engine, alternate model router, or alternate verification/completion authority is introduced. The required Node.js and OpenCode engine ranges are unchanged.

## Release Channel

Version `2.5.0` is a stable semantic version and resolves to npm’s `latest` channel under FlowDeck’s release-channel policy. This release note records release readiness only; it does not publish a package, create a tag, or create a GitHub release.
