# FlowDeck v2.4.1

FlowDeck v2.4.1 is a focused security and reliability patch release delivering strict filesystem jail containment, Git policy hardening, Code Mode selection boundary enforcement, truthful Doctor diagnostics, package dependency closure, and test qualification improvements.

## Key Changes

### 1. Filesystem Path Containment & Jailing (P0)
- **`.codebase` Containment**: Jailed all `.codebase/` read and write operations strictly within the workspace directory using a unified containment primitive (`src/tools/path-jail.ts`). Rejects absolute paths, lexical `..` traversal, prefix collisions, symlink escapes, and root-level symlinked `.codebase` directories pointing outside the workspace.
- **Rust FDX Daemon Repository Jail**: Added an authoritative canonical root parameter (`fdx serve --root <dir>`) resolved at startup. All IPC file operations (`read`, `search`, `outline`, `impact`) are validated against the canonical repository root, preventing escape via relative traversal, symlinks, or absolute paths.
- **TypeScript FDX Fallback Jail**: Applied the same strict repository containment boundary to all TypeScript fallback operations (`nativeReadFallback`, `nativeSearchFallback`, `nativeLsFallback`, `nativeOutlineFallback`, `nativeImpactFallback`, `fdx-batch`), guaranteeing equivalent security when the Rust binary is unavailable.

### 2. Git Read-Only Policy Hardening (P2)
- Hardened Git read-only policy across TypeScript and Rust runtimes.
- Blocked `-c` config overrides unconditionally across both single-token and multi-token formats, along with `--config`, `--config-env`, `--exec-path`, `--output`, `--ext-diff`, `--textconv`, `--paginate`, `--no-pager`, and dangerous hook/editor config options.

### 3. Heidi Code Mode Policy Enforcement (P1)
- Aligned `evaluateCodeModeEligibility` with declared `HEIDI_CODE_MODE_POLICY` selection limits: `maxLines` (80), `maxSourceBytes` (12 KiB), `maxToolCalls` (10), `maxParallelCalls` (4), `maxDependencyStages` (3), and `maxCollectionItems` (25).
- Rejects unbounded/open-ended exploration prompts (`comprehensively`, `exhaustively`, `keep exploring`, `across everything`, `all pages`).
- Enforces strict capability truthfulness: `UNAVAILABLE` when disabled, `UNKNOWN` when enabled without proven execute capability, and `AVAILABLE` only when verified.

### 4. Doctor Diagnostics & Repair Truthfulness (P1)
- Fixed Doctor text formatter to render statuses accurately: `OK` (pass), `WARN` (warning), `INFO` (info), `SKIP` (skipped), and `ERROR` (error). Healthy informational and intentionally skipped checks no longer render as errors.
- Reconciled `autoFixAvailable: true` declarations with actual implemented repair handlers.
- Updated version fallback from `2.0.3` to `0.0.0-unknown`.

### 5. Packaging & Dependency Closure (P1)
- Added `scripts/release-channel.mjs` to npm package files whitelist in `package.json`.
- Added automated tarball verification test proving extracted package runtime script resolution and execution.

### 6. Installer Argument Hardening (P2)
- Converted installer Doctor arguments in `install.sh` to validated Bash arrays (`"${DOCTOR_ARGS[@]}"`), eliminating shell-splitting risks.
- Validates profile input against supported profiles (`minimal`, `recommended-dev`, `full-dev`, `ci`, `release`).
- Removed obsolete uncallable pre-install helper references.

### 7. Test Hardening & Real Coverage Truth (P1)
- Removed false-green test patterns and settlement tautologies (`catch(() => true)`), replacing them with explicit count and error type assertions.
- Real canonical coverage measured at **83.64%** remote / **83.85%** local across 329 eligible source files (threshold: 80%).

### 8. Documentation Alignment (P1)
- Pruned obsolete phantom command references and aligned user documentation with canonical registries (14 agents, 15 commands).
