# FlowDeck v2.2.3

FlowDeck v2.2.3 is a production patch release that fixes a P1 recovery-loop regression discovered in v2.2.2 during repository audit startup, while preserving all inactive-session watchdog protection, shell-failure recovery, Runtime Integrity, Active Parallel Coordination, DSH, FDX, and provider replay behavior.

## Problem & Root Cause

In v2.2.2, legitimate read-only startup discovery queries (`bun --version`, `node --version`, `fdx --version`, `opencode --version`, `git branch --show-current`, `command -v`, `whereis`, and compound pipelines) were falsely classified as mutating or unknown commands by `orchestrator_guard`, triggering `RecoverableFlowDeckBlockError`. Additionally, `LoopDetector.normalizeAction()` failed to extract `args.file` for `fdx-read` calls, collapsing distinct symbol/file reads into identical action keys.

When tool calls returned errors, `detectNoVisibleOutputCompletion()` excluded errored tool parts when computing tool execution counts, misclassifying assistant turns containing tool errors as empty/reasoning-only completions. This immediately scheduled synthetic recovery continuations without single-flight admission checks, causing the recovery directive (`"Continue the current task from the last verified execution state..."`) to re-enter recovery in an infinite loop.

## Changes & Fixes

1. **Read-Only Command & Pipeline Classification**:
   - Added `isVersionOrHelpQuery()` for `--version`, `-v`, `-V`, `--help`, `-h`, and `help` queries.
   - Permitted `command -v`, `whereis`, and read-only `git branch` query flags (`--show-current`, `--list`, `-a`, `-r`) in `orchestrator-guard-hook`.
   - Destructive branch mutation flags (`-d`, `-D`, `-m`, etc.) remain strictly protected.
   - Fixed compound pipelines to attribute category/reason to the exact blocking segment.

2. **Precise FDX & Search Fingerprint Normalization**:
   - Updated `LoopDetector.normalizeAction()` to extract `args.file`, `mode`, `symbol`, line ranges, and search query/dir.
   - Distinct file or symbol reads now produce distinct semantic fingerprints.

3. **Tool Error & Completion Safety**:
   - Updated `detectNoVisibleOutputCompletion()` so any tool execution part (completed, pending, running, or error) counts as active tool execution.
   - Errored tool turns flow through normal tool failure handling and are never misclassified as empty completions.

4. **Authoritative Single-Flight Recovery Admission Gate**:
   - Added `canInjectRecoveryContinuation()` to `RecoveryCoordinator` enforcing `(sessionID, incidentID, generation) -> max 1` outstanding continuation.
   - Rejects duplicate prompts with concrete telemetry (`ALREADY_IN_FLIGHT`, `DUPLICATE_GENERATION`, `TERMINAL_SESSION`, `EXHAUSTED`).

5. **Task Phase Clean Reset**:
   - Clears stale `LoopDetector` session state on manual new task phase boundary in `index.ts`.
