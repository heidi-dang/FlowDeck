# FlowDeck v2.2.5

FlowDeck v2.2.5 is a production maintenance and hardening release delivering comprehensive runtime isolation, multi-agent execution stability, and robust persistence integrity across Linux, macOS, and Windows.

## Key Changes & Runtime Hardening

1. **Modularized FlowDeck Runtime Internals**:
   - Streamlined internal boundaries across orchestration, verification, and persistence layers.
   - Cleaned up configuration dependency graphs to prevent circular initialization paths.

2. **Heidi/OpenCode Execution Reliability**:
   - Seamlessly auto-forwards native `read` and `read_file` calls to high-performance `fdx-read` adapters.
   - Eliminates specialist subagent retry loops under enforced FDX redirection.

3. **Improved Diagnostics & Error Propagation**:
   - Standardized structured error hierarchies with unambiguous error reporting across all sub-systems.
   - Enhanced failure collector with actionable, non-sensitive error summaries.

4. **Doctor Self-Repair Idempotency & Re-verification**:
   - Automated repairs now perform atomic pre-mutation backups of modified configs.
   - Strict post-repair validation guarantees zero regressions across repeated repair invocations.

5. **FDX Native/Fallback Discovery Hardening**:
   - Dynamic PATH observation and binary resolution with robust cache invalidation.
   - Fallback execution paths hardened against timeouts, oversized output buffers, and working directory drift.

6. **Subprocess & Shell Safety**:
   - Refined shell command classifier with transparent `cd <dir>` inspection pipeline support.
   - Enforced structured parser rules for temporary `rm -rf` fixtures scoped strictly to designated temp locations (`/tmp/`, `$TMPDIR`).

7. **Stale-Lock Live-Owner Protection (Contract A)**:
   - Evaluates process liveness using non-destructive signal probing before reclaiming PID lockfiles, preventing deletion of locks held by active host processes.

8. **Repository Lease Coordinator & Multi-Process Safety**:
   - Safe lease acquisition and heartbeat tracking with rollback handling on simulated atomic rename/write failures.

9. **Orchestration Database Ownership & Split-Brain Protection**:
   - Enforces deterministic candidate hierarchy: Project Local (`<dir>/.flowdeck/flowdeck.db`) -> User Home (`~/.flowdeck/flowdeck.db`) -> Temp Directory (`<tmpdir>/flowdeck/flowdeck.db`).
   - Throws `OrchestrationDatabaseAmbiguityError` when multiple unranked fallback candidates exist simultaneously.
   - Guarantees unsupported legacy database locations (e.g. `.opencode/flowdeck.db`) are **not silently adopted**.
   - Verified concurrent multi-process SQLite initialization and PRAGMA integrity.
