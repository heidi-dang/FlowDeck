# Development

## Prerequisites

- Node.js >= 20.0.0
- npm
- Bun >= 1.0.0
- Git

Optional:
- Rust/Cargo (for FDX native tool development)

## Setup

```bash
git clone https://github.com/heidi-dang/FlowDeck.git
cd FlowDeck
npm ci
npm run build
```

## Available Scripts

| Command | Description |
|---|---|
| `npm run build` | Build the plugin bundle (`dist/`) |
| `npm run lint` | Run oxlint with deny-warnings |
| `npm run typecheck` | Run TypeScript type checking |
| `npm test` | Run all tests with Bun |
| `npm run test:coverage` | Run coverage enforcement |
| `npm run validate:skills` | Validate all skill files |
| `npm run validate:docs` | Validate documentation links |
| `npm run verify:fast` | Fast pre-push checks (changed files only) |
| `npm run verify:full` | Full production verification suite |
| `npm run verify:installation:offline` | Offline installation verification |
| `npm run verify:installation` | Full installation verification |
| `npm run build:fdx` | Build the FDX Rust binary |
| `npm run check:fdx` | Check FDX binary version |
| `npm pack --dry-run` | Check package contents |

## Development Workflow

1. Create a branch from `main` with a descriptive prefix:
   - `feat/` for features
   - `fix/` for bug fixes
   - `docs/` for documentation
   - `refactor/` for refactoring
   - `test/` for test improvements

2. Make focused changes and run targeted tests:
   ```bash
   npm test -- tests/<file>.test.ts
   ```

3. Before committing, run fast checks:
   ```bash
   npm run verify:fast
   ```

4. Before opening a PR, run the full gate:
   ```bash
   npm run verify:full
   ```

5. The CI pipeline runs on GitHub Actions and is the authoritative cross-platform gate.

## Verification Gates

### Fast Mode
For normal development changes, `npm run verify:fast`:
- Lints only changed files
- Runs incremental typecheck
- Runs focused tests for changed source directories
- Validates skills and docs paths when relevant

### Full Mode
Before final PR approval, `npm run verify:full`:
- Full lint
- Full typecheck
- All tests
- Coverage enforcement (80% threshold)
- Skills validation
- Docs validation
- Git diff check
- Package dry-run
- Build
- Rust gates (when crates/fdx/ changes)

## Installation Testing

```bash
# Test installation in an isolated environment
npm run verify:installation:offline

# Test with OpenCode runtime (requires provider credentials)
npm run verify:installation
```

## Project Structure

```
src/
  index.ts              Plugin entry point
  config/               Configuration schema and loading
  agents/               Agent registry and routing
  hooks/                Session lifecycle and tool guards
  services/             Governance, validation, recovery
  tools/                FlowDeck tools
  skills/               Skill files
  commands/             Slash command definitions
  mcp/                  MCP server configurations
crates/fdx/             Rust native tools (optional)
scripts/                CLI, installer, validators
tests/                  Test files
docs/                   Documentation
```

## FDX Development

```bash
cargo build --manifest-path crates/fdx/Cargo.toml
cargo test --manifest-path crates/fdx/Cargo.toml
cargo fmt --manifest-path crates/fdx/Cargo.toml --check
cargo clippy --manifest-path crates/fdx/Cargo.toml --all-targets
```

## Rules

- Do not edit files in `dist/` — they are generated by `npm run build`.
- Do not commit secrets, API keys, or credentials to any file.
- Do not use `as any` or `@ts-ignore` to suppress type errors.
- Focused tests during development; full tests before PR.
